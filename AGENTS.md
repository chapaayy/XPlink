# AGENTS — обязательные правила для людей и ИИ

1. Прежде чем менять код, прочитать `docs/START_HERE.md`, `docs/PROJECT_MAP.md`, `docs/SECURITY_MODEL.md`, `docs/ROADMAP.md` и затрагиваемые ADR.
2. Найти владельца функциональности в `docs/PROJECT_MAP.md`; конкретные файлы — в `docs/FILE_INDEX.md`; менять минимальный набор модулей.
3. Не импортировать Matrix SDK вне `packages/matrix-adapter`, кроме типизированной интеграционной композиции `apps/web/src/app` и объявленных UI границ. Без собственного E2EE-протокола.
4. **Никогда** не пересылать plaintext переписки, crypto keys, access tokens и пароли в backend, стороннюю аналитику, логи или тестовые артефакты. Не превращать ошибки в дампы объектов SDK.
5. Любые изменения crypto, membership, storage, permissions требуют негативных тестов «отправка заблокирована», документации безопасности и при необходимости нового ADR.
6. Поддерживается ровно один активный Rust Crypto клиент на одно хранилище. Не обходить Web Locks и не создавать второй MatrixClient с активной crypto store.
7. Версии обновляются адресно, с lockfile, changelog, проверкой API и E2E. Не менять весь стек разом.
8. Перед PR: `pnpm format:check`, `pnpm lint`, `pnpm typecheck`, `pnpm test`, `pnpm build`, `pnpm docs:check`. После инфраструктурных изменений — Docker E2E + restart/restore проверки.
9. Новый важный файл описать в `scripts/file-manifest.json`, выполнить `pnpm docs:generate`; индекс проверяет CI. Новый пакет/сервис должен иметь owner и реальную задачу.
10. Сохранять путь восстановления: не удалять конфиги/тома/миграции без backup и rollback. Новые этапы не начинать без запроса.
11. Отчёт по этапу: **Изменено / Не изменено / Проверено / Что осталось / Риски / Файлы** с честным указанием непрошедших проверок.
