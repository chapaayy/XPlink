# Жизненный цикл ключей — stage 1

На каждом новом `device_id` SDK инициализирует Rust Crypto; ключевой материал живёт в browser IndexedDB, **не** в PostgreSQL. Сообщения в зашифрованной комнате шифруются на отправителе; обмен ключами осуществляется стандартным SDK. Сессия браузера в `sessionStorage` содержит токен входа, а не приватные encryption keys.

**Не реализовано**: cross-signing, manual verification, secret storage bootstrap, recovery key, экспорт/импорт ключей, trust UI, отзыв удалённого устройства. После очистки IndexedDB/нового входа старые сообщения могут не расшифровываться. Это блокер для production; этап 2 обязан закрыть его реальным тестом двух устройств и восстановления истории.
