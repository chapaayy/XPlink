# Политика разрешений — XPlink Stage 3

XPlink не вводит фиктивную таблицу ролей, проверяемую лишь интерфейсом. **Источником прав остаётся Matrix `m.room.power_levels`**, а Synapse самостоятельно авторизует отправку событий, приглашения, kick и правку state.

## Роли отдельного E2EE-канала

| Роль | Level | Базовые полномочия |
| --- | ---: | --- |
| Участник | 0 | Читать E2EE сообщения при наличии ключей; писать в обычном канале |
| Модератор | 50 | Писать в канале «только модераторы», приглашать/исключать при разрешениях комнаты |
| Администратор | 100 | Настройка ролей и power levels при разрешении сервера |

Полномочия не «наследуются» автоматически из пространства в каналы: Matrix Spaces группируют комнаты, но у каждой отдельное membership и состояние прав. Пользователя нужно пригласить в каждую нужную E2EE-комнату. При создании пространства XPlink не делает все каналы публичными или автоматически вступаемыми.

Режим «Только модераторы могут писать» задаёт `events_default: 50` и `events['m.room.encrypted']: 50`. Это существенно: зашифрованные `m.room.message` и `m.reaction` имеют **wire type `m.room.encrypted`**. Проверка только `m.room.message` на сервере была бы обходом. Обычный режим возвращает порог 0. Все операции отправляют штатные Matrix API и отклоняются при HTTP 403; UI не является security boundary.

**Изменение ролей** применяет `MatrixClient.setPowerLevel(roomId, userId, level)` и не обходит требование членства в комнате. Никаких SQL-прав или локальных таблиц доступа.

## Состояние и ограничения

- Отправка E2EE проверяет и состояние комнаты, и статус Rust Crypto, и изменённые identity. Любые вложения/реакции проходят тот же fail-closed gate.
- При исключении из комнаты исходящий Megolm-сеанс сбрасывается; уже полученные ключи и сообщения невозможно отобрать у исключённого пользователя.
- Права на пространства, категории и дочерние каналы независимы. Это сознательное ограничение протокола для первого рабочего текстового продукта; механизм глобальных Discord-подобных кастомных ролей потребовал бы отдельного server-side authorization design и не должен имитироваться в UI.
