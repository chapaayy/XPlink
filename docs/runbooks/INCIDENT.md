# Incident response — этап 1

При подозрении на компрометацию остановить внешнюю публикацию (пока она запрещена), сохранить необходимые метаданные без plaintext/секретов, проверить авторизованные устройства через Matrix, отозвать скомпрометированные сессии через штатные API. Сменить затронутые серверные credentials лишь с планом сохранения доступа. Не обещать, что отзыв ключей удаляет уже прочитанные сообщения. Для настоящего инцидента нужен отдельный разбор модели угроз и план уведомлений (этап 6).
